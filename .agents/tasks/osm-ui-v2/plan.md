## Root causes found (read before items 2–6)

Map ("poucos pontos de longe" + "piscam e somem ao mexer"):

1. `MIN_COMMUNITY_ZOOM = 15` in `communityLayer.ts` while the map opens at zoom 13 (`minZoom` 12), and the RPC `pontos_comunidade_bbox` (migrations_osm_02) returns nothing for `p_zoom < 15` and raises `bbox_grande_demais` for spans > 0.25°. Below 15 there are no community points at all; zooming out from 15 to 14 clears every community marker at once.
2. The fetch uses the exact viewport (`map.getBounds()`, no padding) and refetches on every `moveend`. Any pan shows an empty strip until debounce (400 ms) + network, and markers that leave the edge are removed.
3. The server aggregates each grid cell only over the points INSIDE the bbox. A cell cut by the bbox edge changes `quantidade`/centroid between pans, and a 2-point cell cut to 1 point flips its key from `g:…` to `p:<id>`, so the marker is destroyed and recreated (blink). The cell size also doubles when the bbox has more than `p_max_itens` cells, which re-keys every cluster.
4. `reconcile()` skips existing keys (`if (this.markers.has(row.chave)) continue;`), so a cluster whose count/centroid changed keeps a stale count/position until it is re-keyed.
5. `setSelected(null)` removes the selected community marker immediately and it only comes back after the next refresh (visible gap on deselect).

Labels: `.rsb-marker--community .rsb-pin-label { display: none; }` in `globals.css` hides community labels except selected/focused. Official labels (`.rsb-pin-label`) are always visible, not zoom-dependent.

These are code-reading findings. The user's reports (few points from far, flicker, missing labels) must also be confirmed and re-checked at RUNTIME in items 3 and 6. Do not mark any of them "already fine" without the runtime evidence.

## Decisions

- D1 Zoom thresholds: `MIN_COMMUNITY_ZOOM = 12` (= map `minZoom`), so the layer is on at every zoom, including the initial 13; no threshold crossing that clears markers. Selection/recenter `flyTo` keeps its old minimum of 15 through a new constant `SELECT_FOCUS_ZOOM = 15`.
- D2 Server grid (new migration 04): cell = 80 px at zoom ≤ 14 and 56 px at zoom 15–16 (was 64 px everywhere); individual points from zoom 17 (was 18) when the count fits. Cell size depends only on zoom, and each touched cell is aggregated over ALL its points (cell-aligned envelope), so keys, counts and centroids do not depend on where the bbox edge falls. Accepts `p_zoom >= 12`, bbox span up to 1.5° per side (desktop 1920 px at zoom 12 with padding ≈ 1.32°). The doubling loop stays only as an overload guard (never reached with today's ~174 points). 80 px > the 48 px cluster bubble, so neighbouring bubbles do not overlap at city zoom; 56 px gives more individual pins at street level.
- D3 Client fetch: padded bbox `bounds.pad(0.5)` (2× width and height), clamped to 1.5° per side; no refetch while the viewport stays inside the last fetched (or in-flight) padded bbox with the same zoom/category/excluded id; debounce 300 ms; stale responses discarded by sequence number; markers are never cleared before the new response arrives; `MAX_ITENS = 299` (+1 selected = 300 DOM markers max; the padded area is 4× the viewport).
- D4 Pre-migration degradation: until the user runs migration 04 the old RPC returns `[]` below zoom 15 (same as today) and may raise `bbox_grande_demais` for padded spans > 0.25° (very wide screens). On that specific error the client retries once with the unpadded viewport. Nothing else breaks.
- D5 Labels: community pins show the name label always, same rule as official pins (official labels are not zoom-dependent). Clusters never show a place name, only the count. Community labels get `max-width: 160px` + ellipsis (full name stays in `title`/`aria-label`), and community markers stay below officials (`zIndexOffset: -1000`, unchanged). Outline (hollow) pin style unchanged.
- D6 Em mapeamento screen: new component `CommunityPointSheet` (mobile < 1280 px: bottom sheet; desktop ≥ 1280 px (`xl`): left side sheet 390 px like PointDetails). page.tsx renders it instead of `PointDetails` whenever `activeDetailsPoint.status === "em_mapeamento"`, which covers every entry point (mobile "Ver Detalhes do Local", desktop pin click, ProfileView history, voice assistant `goToPoint`, "Sugerir um local" → existing point). The mobile preview `BottomSheet` stays unchanged. `PointDetails.tsx` is NOT edited (guarantees the official screen is unchanged and avoids its pre-existing lint errors); its `isMapping` branch becomes unreachable and is left as is.
- D7 Content of the sheet, in order: header (category as plain small uppercase text, name, "Em mapeamento" in secondary text, close button, and a single "Ouvir" play/pause button only when Voz Alta is on); ONE discreet notice line `role="note"`: "Informações da comunidade, ainda sem dados oficiais de acessibilidade." (same sentence as the preview sheet; content is community-sourced, so it must stay, but as one secondary line instead of the big card); feedback form (user listed it first and it is the main action); "Condições recentes". Removed: address, "Como chegar", OSM block (horário/telefone/site/"Segundo o OpenStreetMap"), the 3-state resource list card, avatars/names, star rating.
- D8 Consensus: kept only as ONE secondary text line inside "Condições recentes", shown only when `consenso_recursos` returns rows ("Relatado pela comunidade: Banheiro adaptado (3 pessoas) · …"). No "não verificado" rows. It fits the minimal design and keeps RF-4.6's attribution wording.
- D9 Resource tiles: `ReportResourcesFieldset` becomes a grid of toggle tiles in the visual language of the official `AccessibilityChip` (PointDetails.tsx: `rounded-2xl border p-3`, icon `w-7 h-7`, `font-black` label, on = `border-brand bg-brand-light text-brand`), same icons as the official chips. On = `"tem"` in `recursos`; off = key omitted. "Não tem" can no longer be reported (accepted by the user), so consensus can only converge to "tem". `relato_recursos_validos` still accepts this payload; no SQL change for the tiles. Same props (`value`, `onChange`), so the only other consumer (PointDetails' unreachable `isMapping` branch) still compiles. Official points never used this fieldset, so nothing changes for them.
- D10 Tests: no frontend test framework exists. Pure logic goes into dependency-free `.ts` modules tested with `node --test` (Node v24.13 strips TS types natively) from `.mjs` files under `scripts/ui/` (not type-checked by `tsconfig`, which only includes `.ts/.tsx/.mts`).
